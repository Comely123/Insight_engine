# 云端部署决策备忘（Phase 5）

## 结论（当前）

**默认不上云。**  
本阶段交付为：本地性能基准 + 备份恢复 + 运维文档。个人研究、单机 Streamlit 使用场景下，本地版已满足 Phase 0–4 能力。

远程仓库：[Comely123/Insight_engine](https://github.com/Comely123/Insight_engine) 仅用于代码版本管理，**不**托管用户私有数据库、视频或 API Key。

## 何时再考虑上云

同时满足多项时再评估：

1. 需要 7×24 无人值守运行  
2. 需要远程多人共享同一实例  
3. 本地 CPU/磁盘成为可测量瓶颈（有基准对比）  
4. 本地备份可靠性不足  

## 若未来上云（最小可行设想，未实施）

| 项 | 建议方向 |
|---|---|
| 计算 | 单台小规格 Linux（2 vCPU / 4GB 起），按实测再升 |
| 应用 | 仍可先单进程 Streamlit 或后续再评估 FastAPI |
| 数据库 | 继续 SQLite（单实例）或再评估 PostgreSQL（多写并发时） |
| 存储 | 数据盘与系统盘分离；媒体默认路径引用，不默认上传原片 |
| 网络 | 仅开放 HTTPS；禁止公网暴露 DB 端口 |
| 凭据 | 环境变量/密钥管理服务；不入库 |
| 备份 | 定期快照 + 恢复演练 |
| 费用 | 需按当时报价估算；此处不虚构精确数字 |

## 不上云的替代方案

- 本机定时 `backup_db.py`  
- 需要远程时：自建 VPN/SSH 隧道访问本机（仍不上公网管理面）  
- 代码用 GitHub 同步；数据留在本地加密盘  

## 禁止事项

- 未经用户明确授权创建云资源或产生持续费用  
- 默认上传原始视频、个人信息或 API Key  
- 多实例共享同一 SQLite 文件于网络盘
